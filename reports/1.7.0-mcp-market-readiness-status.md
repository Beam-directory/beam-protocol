# Beam 1.7.0 MCP market-readiness status

Live-checked on 2026-08-23. This report separates the working hosted pilot from
the evidence still required for a release or a market claim.

## Current verdict

`LIVE READ-ONLY HOSTED PILOT VERIFIED / GROK CLOUD CONNECTOR AND BUSINESS DOGFOOD PENDING`

The hosted protocol path is no longer a design-only candidate. The public
OAuth-to-MCP flow works end to end. Beam 1.7.0 is nevertheless not approved for
release because the Grok account connection, external operator evidence, a real
business-assurance target, and the Keycloak image risk decision are still open.

## Live hosted pilot proven

- Three single-machine Fly.io apps are running in `fra`: a private PostgreSQL
  identity database, Keycloak, and the public MCP resource server.
- PostgreSQL uses an encrypted 1 GB volume with snapshots. The estimated steady
  cost remains approximately USD 11.41/month before traffic, below the approved
  USD 15/month ceiling.
- `identity.beam.directory` and `mcp.beam.directory` have issued TLS
  certificates. The MCP health endpoint returns HTTP 200, protected-resource
  metadata returns HTTP 200, and an unauthenticated MCP initialize request
  returns HTTP 401 with the exact RFC 9728 metadata URL and `beam:read` scope.
- Keycloak issues a 300-second token through Authorization Code + PKCE S256.
  RFC 8707 resource indicators bind the token audience to exactly
  `https://mcp.beam.directory/mcp`.
- The token contains `beam:read`, contains no `beam:send`, and is active through
  confidential introspection by the canonical resource-server client.
- The official MCP client connected to the public URL, listed exactly
  `beam_prepare_handoff` and `beam_status`, and successfully called
  `beam_status`.
- `beam_send` was neither advertised nor called. No Beam message was sent.
- The deployed MCP image is
  `sha256:fc75f33105770f89ae6324d63a9ffc60d3ea0338f6ddee37523673ec9707a832`.
  Its Node process runs as UID 1000; all mounted secrets are mode `0400`, and
  secret values are absent from the container environment.
- The redacted OAuth/PKCE smoke artifact is mode `0600` outside the repository;
  SHA-256:
  `068a0a2b5303c17a9415df432865ae4f2fce830f46161dbb26f82cffcda445f8`.

The structured, explicitly non-gate-eligible snapshot is in
`reports/1.7.0-mcp-hosted-pilot-live-evidence.json`.

## Current verification

- Full workspace suite: 248 tests passed.
- Full TypeScript typecheck passed.
- Local signed MCP handoff E2E passed.
- Hardened container MCP E2E passed with UID 1000, mounted secrets, a
  business-tier fixture, exactly two read-only tools, and no advertised send.
- Current local High/Critical scan summaries:
  - MCP image: 0 findings;
  - PostgreSQL image: 0 findings;
  - Keycloak 26.7.1 image: 14 unique findings.

The Keycloak finding count is a release blocker, not hidden pilot debt. The
current upstream image is usable only under an explicit, time-bounded read-only
pilot exception; market release requires patched upstream dependencies, a
separately justified managed identity provider, or an accepted security
exception with compensating controls.

## Grok state

- Grok Build CLI 1.0.5 has the public Beam MCP URL in its user configuration.
- `grok mcp doctor beam` reaches the server and correctly detects that OAuth
  authorization is required. The non-interactive doctor command does not open
  or complete that authorization flow.
- In the signed-in Grok web account, a custom connector named
  `Beam (read-only pilot)` is filled with the public MCP URL. The final
  `Connector hinzufügen` action is deliberately still pending because it
  creates persistent OAuth access and requires action-time approval.
- Grok connection and tool invocation are therefore not yet claimed as
  verified.
