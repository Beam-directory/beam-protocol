## Selected hosted pilot design (not provisioned)

- `mcp.beam.directory`: one dedicated, send-disabled Beam MCP tenant;
- `identity.beam.directory`: Keycloak `26.7.1` with PostgreSQL, closed user
  registration, PKCE `S256`, short-lived tokens, revocation-aware
  introspection, and a pilot-only operator population;
- OAuth access tokens must carry both the exact MCP resource audience
  `https://mcp.beam.directory/mcp` and the confidential introspection-client
  audience; `beam:read` is the only pilot MCP scope;
- the current Keycloak OCI index is pinned for the pilot build as
  `quay.io/keycloak/keycloak@sha256:f1f1f01e472c8a78df40d8f2a49a925274eda4d3d80d5f6edbb5c880ee3c01c6`;
- managed ZITADEL was evaluated as a lower-operations alternative, but its
  current dynamic-client-registration flow accepts and ignores the RFC 8707
  `resource` parameter and uses a project-wide audience. That does not satisfy
  this candidate's exact-resource audience invariant, so it is not the default
  pilot provider;
- the `mcp.beam.directory` and `identity.beam.directory` DNS names currently
  have no public records. No app, database, volume, OAuth tenant, or DNS record
  has been created for this design.

At current Fly list pricing, a continuously running 256 MiB MCP machine, 1 GiB
Keycloak machine, 512 MiB PostgreSQL machine, and a small database volume are
roughly USD 12/month before transfer and optional extras. Provisioning requires
a separate cost and live-infrastructure GO.
