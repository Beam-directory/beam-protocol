# Beam 1.8.0 Release Notes

Release status: `draft`

## Summary

Beam `1.8.0` adds the trust chain behind an agent: the organization proven by its full domain, the responsible person with a verified identity, and a person-signed mandate that limits what the agent may do. The directory no longer generates agent private keys. Consequential intents outside a mandate are held for a person instead of being delivered.

This release contains PRs #211, #212, #214, #215 (directory trust layer), #210 (hosted MCP pilot profiles), and #213 (public site).

## Highlights

### Organization identity and key custody (#211)

- an organization is bound to its full registrable domain; `coppen.de` and `coppen.at` are separate organizations
- domain proof by DNS TXT or `https://<domain>/.well-known/beam-verification`
- Handelsregister or LEI filings are recorded per organization and reviewed manually
- organization and workspace issuance require a client-generated Ed25519 public key; the directory no longer returns a private key
- signing-key rotation requires the current key's signature, the organization API key, or the active responsible person
- `PATCH /agents/:id/config` changes to `dhPublicKey` or `httpEndpoint` require a fresh signed nonce, the organization key, or an admin session
- pending claims use a `--` namespace (for example `coppen--de`); the short label is granted only after domain verification and only if it is free
- `/health` reports `db.domainUniqueIndex`; duplicate domains that prevent the unique index are logged and audited

### People and hierarchy (#212)

- organization people with role, supervisor, and a rights ceiling
- invitations accepted with a client-generated public key
- KYC through a manual adapter; only an operator review sets a person to verified or rejected
- Personio or Entra snapshot import as an upsert by external id or email
- a new person key returns KYC to `pending` and revokes that person's mandates
- offboarding suspends every agent the person is responsible for

### Mandates, revocation, trust assertion, acceptance rules (#214)

- person-signed mandates; scopes cannot exceed the person's rights, and a mandate requires a KYC-verified person and a verified organization domain
- revoked mandates and delegations cannot be replayed
- the person, their active supervisor, or the organization key can revoke a single mandate
- `GET /agents/:id/trust-assertion` is signed by the stable directory issuer key; public agents only, or the agent itself, accepted contacts, and the organization key; person ids are SHA-256 references and the assertion includes `suspended`
- recipient acceptance rules carry a monotonic version, a nonce, and a timestamp
- the responder signature is stored in `intent_log.result_signature`

### Untrusted content and limits (#215)

- message and file content is delivered as labeled untrusted data, separate from sender assertion and metadata
- `order.place`, `payment.submit`, `schedule.commit`, `file.send`, and `file.forward` are checked against the sender's mandate; anything outside it returns HTTP 202 `APPROVAL_REQUIRED` and is not delivered
- daily order and payment limits per mandate, counted on the server UTC day and released when delivery fails
- approvals are matched by exact organization; suspended agents, people, and organizations are refused on WebSocket, intents, delegations, and Network
- operator suspension and unsuspension with a required note and audit entry
- the TypeScript SDK returns `{ executed: false }` for a held intent; the CLI, MCP gateway, Python SDK, and message bus treat HTTP 202 as a hold, not a delivery

### Hosted MCP pilot (#210)

- the default Fly profile `ops/mcp-pilot/fly/mcp.fly.toml` keeps Network and send disabled
- a separate `mcp.send.fly.toml` enables Network reads, token-confirmed writes, and a limit of 30 sends per hour; it is not deployed as part of this release

### Public site (#213)

- new landing page in English at `/` and German at `/de`, with `hreflang`, localized Open Graph images, `robots.txt`, and `sitemap.xml`
- onboarding at `/start` and `/de/start`; keys are generated in the browser, and steps the directory does not serve yet are marked as not available

## Breaking changes

- workspace and organization clients must generate the Ed25519 key and send `publicKey`
- `bk_` alone can no longer rotate a signing key or replace `dhPublicKey` / `httpEndpoint`; Network, the MCP pilot scripts, and the OpenClaw scripts sign the config request and still work against directory 1.7.0
- `POST /agents/keypair/x25519` is removed
- `client.send()` in the TypeScript SDK returns `ResultFrame | ApprovalRequired`
- npm 10 or newer is required to install the repository

## Operations

- set `BEAM_DIRECTORY_SIGNING_PRIVATE_KEY` and `BEAM_DIRECTORY_SIGNING_PUBLIC_KEY` on the directory before deploy; without them the trust assertion returns HTTP 503 `ISSUER_KEY_REQUIRED`
- schema changes are additive and run on start (new tables `org_registry_filings`, `persons`, `person_invitations`, `mandates`, `acceptance_rules`, `intent_approvals`, `mandate_order_spend`, `abuse_reports`; new columns on `orgs`, `agents`, `acceptance_rules`, `delegations`, `intent_log`, `beam_connections`; unique indexes on organization domain and `delegations.payload_hash`)
- rollback to the 1.7.0 image leaves the new tables and columns in place; suspensions, mandates, and approvals are then not enforced

## Known limitations

- free-text intents such as `conversation.message` are not bound to a mandate; recipients must not act on free text
- intents pass through the relay in plaintext; end-to-end encryption applies to Network chats and files
- approvals can still be decided with the organization key alone (audited as `via: org-key`); an approval does not execute the held intent
- `--` names such as `ab--de` are valid Beam labels but can look like Punycode in some interfaces

## Release Gate

The tag workflow requires `reports/1.8.0-mcp-pilot-evidence.json` before publish and directory deploy. That file must contain observed data from the hosted read-only pilot, including an external operator run and a business-tier target lookup. It is not part of this draft.
